# Spec — 메뉴명 Candidate Matching 후처리 (S-15 ~ S-17)

## Why

- **페르소나**: 음성으로 카페 메뉴를 주문하는 고령 사용자
- **상황**: GPU 재평가(`compare_both_150_seed-42.csv`)에서 메뉴명 keyword recall이 Baseline 0.000 / QLoRA 0.007이다. **실측 원인은 평가셋에 메뉴명이 없어서** — 150샘플 정답 어디에도 10종 메뉴명이 등장하지 않음(분모 0). 이는 S-10(도메인 평가셋 필요)을 뒷받침하는 근거다. 메뉴 보정의 효과는 실제 STT가 메뉴명을 오인식했을 때를 가정한 합성 메뉴 발화로 측정해야 한다.
- **문제**: STT가 정확히 전사하지 못한 메뉴명을 그대로 두면 후속 NLU·Order Engine에 잘못된 메뉴가 전달된다. 단, "무조건 고친다"로 가면 사용자가 말하지 않은 메뉴를 끼워 넣는 부작용(환각 보정)이 생긴다.
- **측정 지표**: 합성 메뉴 발화에서 교정 성공률, 교정 부작용(환각 보정) 비율, 실제 150샘플에서는 무영향 확인

## Goal

- **S-15**: STT 결과(가설)에서 메뉴 DB(`src/config/menu.json`) 후보와 유사한 문자열을 찾아 정규 메뉴명으로 교정한다.
- **S-16**: 자동 보정을 허용할 유사도 하한(Threshold)을 정의하고, 데이터(validation)로 하한을 선정한다.
- **S-17**: 보정 전/후 CER · WER · 메뉴명 recall · 환각 보정 비율을 측정해 후처리 효과와 부작용을 수치로 제시한다.
- **성공 기준**:
  - 단위 테스트(AC) 통과
  - 합성 메뉴 발화 320건(정상 20 + 메뉴명 변형 300)에서 기본 Threshold(0.65)로 메뉴명 변형 발화 교정 성공률 100%(300/300) ≥ 90%
  - 합성 비메뉴 발화(공격적 케이스 포함)에서 환각 보정 비율 0% (기본 Threshold)
  - 실제 150샘플에는 메뉴명이 없어 보정이 발생하지 않음(무영향) — S-10 근거로 기록
- **Out of Scope**: 수량/옵션/가격 문자열 보정(이번 범위는 메뉴명만), 형태소 분석 기반 보정, NLU 연동, 음성 입력 파이프라인과의 실시간 결합

## What

**Happy Path**
1. STT 가설 텍스트(예: "자몽에이들 한 잔 주세요")를 받는다
2. `CandidateMatcher`가 공백·대소문자를 무시한 정규화 문자열에서 메뉴 후보를 탐색한다
3. 정확 일치(score 1.0) 또는 유사 일치(score ≥ threshold)를 찾는다
4. 일치 구간을 정규 메뉴명("자몽에이드")으로 교정한다
5. 교정 결과(전체 텍스트, 변경 목록, 변경 여부)를 반환한다
6. 평가 스크립트가 보정 전/후 지표를 비교한다

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 메뉴명이 정확히 인식됨 | 교정은 "일치"로 기록하되 변경 여부(changed)=False |
| EC-02 | 한 글자 대체 오인식 (자몽에이들) | 유사도 ≥ threshold면 정규 메뉴명으로 교정 |
| EC-03 | 후보와 무관한 문장 | 교정 없음 (텍스트·변경 목록 그대로) |
| EC-04 | 띄어쓰기 변동 (카페 라떼) | 공백 무시 정규화 → 동일 일치 취급 |
| EC-05 | 어미/조사 부착 (카페라떼를) | 정확 부분 문자열로 처리 → 조사 보존 |
| EC-06 | 유사 메뉴명 (카페라떼 ↔ 바닐라라떼/말차라떼) | 편집 거리 유사도로 구분, 임계값 미달이면 교정 안 함 |
| EC-07 | 한 문장에 메뉴 2개 | 비중첩 일치 모두 교정 |
| EC-08 | 빈 텍스트 | 교정 없음, 오류 없음 |

## How

```
모듈: src/adapters/stt/postprocess.py  (외부 의존성: stdlib만 — numpy 필요 없음)

class CandidateMatch:
    item_id: str          # menu.json item id
    canonical: str        # 정규 메뉴명 (menu.json name)
    original: str         # 교정된 구간 원문 (정규화 후)
    score: float          # 일치 점수 (정확 일치 1.0)
    start: int            # 정규화 문자열 내 시작 오프셋
    end: int              # 정규화 문자열 내 종료 오프셋 (배타)

class CorrectedText:
    text: str             # 교정 후 전체 텍스트 — 메뉴 구간만 교체, 원문 공백·비메뉴 텍스트 보존
    changes: list[CandidateMatch]
    changed: bool         # 원문(정규화)과 다른 구간이 있었는지

class CandidateMatcher:
    def __init__(self, threshold: float = 0.65,
                 menu_path: Path | None = None) -> None
      # menu_path 기본값: src/config/menu.json (items[].name 10종)
      # 후보는 길이 내림차순 정렬해 짧은 이름이 긴 이름을 가리지 않게 함

    def match(self, text: str) -> CorrectedText
      # 1) norm = 공백·대소문자 제거 정규화 (원문 인덱스 역매핑 유지)
      # 2) 후보별 정확 부분 문자열 탐색 (score 1.0)
      # 3) 정확 일치가 없으면 "토큰 그룹 길이 == 후보 길이" 연속 토큰 그룹으로 유사도 탐색
      # 4) score 내림차순 greedy 비중첩 선택
      # 5) 메뉴 구간만 정규 메뉴명으로 교체해 재구성 — 나머지 원문·공백·대소문자 보존

    correct = match  # 동의어 제공

정규화: normalize(text) = "".join(text.strip().lower().split())
  - metrics._normalize와 동일 정책 (공백·대소문자 무시)
  - CER 전후 비교에는 동일 공백 제거 정규화를 적용해 "메뉴 보정 효과만" 격리
  - WER 전후 비교에는 normalize_wer(text) = " ".join(text.strip().lower().split())을
    사용해 단어 경계(공백)를 보존한다. 공백을 지우면 문장 전체가 단어 하나가 되어
    WER이 "문장 전체 일치 여부"에 가까워지므로, 단어 단위 오류율로 계산하려면
    앞뒤 공백 제거·연속 공백 축약·대소문자 정규화만 적용한다.

유사도: 정규화 편집 거리 유사도 (Levenshtein)
  similarity(a, b) = 1 - levenshtein(a, b) / max(len(a), len(b))
  - 짧은 메뉴명(4~5자)에서 한 글자 오류가 bigram 계열 유사도보다 관대하게 잡힘
    (예: 자몽에이들 ↔ 자몽에이드 = 0.8)
  - 유사 메뉴명 구분: 카페라떼 ↔ 말차라떼 = 0.5, ↔ 바닐라라떼 = 0.4

탐색 대상: 토큰(공백 기준 단어)의 연속 그룹 중 정규화 길이 합이 후보 길이 L과
일치하는 것만 사용 (EC-05 조사 보존)
  - 단일 토큰: "자몽에이들" ↔ 자몽에이드 (L=5)
  - 복수 단어 메뉴: "크로플"+"아이스마림" ↔ 크로플아이스크림 (합 8 == L)
  - 부분 단어 차단: "아이스크림"(L=5)은 아이스티(L=4) 후보와 길이 불일치 →
    환각 보정 원천 차단 (비교: 아이스크 ↔ 아이스티 유사도 0.75여도 대상 아님)
  - 예: "카페라떼를"은 "카페라떼" 정확 부분 문자열로 처리 → "를" 보존

기본 Threshold: 0.65
  - S-16 스윕(0.65/0.70/0.75/0.80/0.85) 결과: 환각 보정은 모든 Threshold에서 0건,
    오교정도 0건. 교정 성공률(메뉴명 변형 발화 300건 기준)은 0.65에서 100%(300/300)로
    90% 기준을 충족하고, 0.70~0.75는 90.0%(270/300)로 감소한다.
  - 무교정 30건(0.70/0.75 기준)은 전부 밀크티(3자, 1자 오류 유사도 0.667,
    0.65~0.70 구간)이며, 유사 메뉴명(카페라떼 ↔ 말차라떼 0.5, ↔ 바닐라라떼 0.4)은
    0.65 미만으로 오교정되지 않는다.
  - 3글자 이하 메뉴명의 1자 오인식은 유사도 0.667로 0.65를 넘지만,
    상대적으로 짧아 threshold를 더 높이면 교정에서 누락되는 한계가 있다.
```

**S-17 지표** (메뉴명 변형 발화 300건 기준)
- CER / WER: corpus-level (문장별 평균이 아닌 전체 reference/hypothesis 집계)
  - reference는 **전체 정답 발화** (메뉴명이 아니라 템플릿 전체)
  - metrics.corpus_cer / corpus_wer 사용
  - CER은 공백 제거 정규화(normalize), WER은 단어 경계 보존 정규화(normalize_wer) 사용
- 메뉴명 recall: aggregate_keyword_recall (전체 matched/total) — 결과 텍스트에 정답 메뉴명 포함 여부
- 환각 보정 비율: 비메뉴 발화 중 교정(changed=True)된 비율
- 기본 Threshold 0.65 기준: CER 0.1042 → 0.0000, WER 0.2632 → 0.0000,
  메뉴명 recall 1.0000 (300/300), 환각 보정 0.0000 (0/7)

**S-17 평가 스크립트**: `src/adapters/stt/compare_postprocess.py`
- 입력 1(실제 데이터): `models/whisper-medium-qlora/lr-2e-05_ep-5/compare_both_150_seed-42.csv`
  - 정답 150건 중 메뉴명 등장 0건 확인 → 보정 0건, CER/WER 전후 동일(무영향)
  - Baseline CER 0.2435, QLoRA CER 0.2150 (공백 무시 정규화 기준) — S-10 근거
  - Baseline WER 0.4929, QLoRA WER 0.4635 (단어 경계 보존 정규화 기준)
- 입력 2(합성 메뉴 발화, `--synthetic`): 메뉴명 정상·오인식·비메뉴 발화로 효과·부작용 측정
  - 정상 발화: "카페라떼 한 잔 주세요" 등 각 메뉴 2템플릿 × 10메뉴 = 20건
  - 오인식 발화: **메뉴명 내부의 글자 1자만** 대체해 생성 (대체 문자는 원래 글자와
    반드시 다른 문자 — "한 글자 오인식" 보장, 시드 고정으로 메뉴당 15건 × 10메뉴 ×
    2템플릿 = 300건 전부 메뉴명 변형)
  - 비메뉴 발화: "안녕하세요", "아이스크림 주세요", 수량만 있는 발화 등
  - 산출: 메뉴명 변형 발화 기준 교정 성공률(결과 텍스트에 ground truth 메뉴 포함),
    오교정, 환각 보정(비메뉴가 교정됨), 전체 발화 기준 corpus CER/WER
- 스윕: [0.65, 0.70, 0.75, 0.80, 0.85] → Threshold별 성공률/환각 보정 표 (S-16)

## AC (Given-When-Then)

**AC-01 · 정확 일치 교정**
- GIVEN: `CandidateMatcher()` 기본값, 가설 "카페라떼 한 잔 주세요"
- WHEN: `correct()` 호출
- THEN: 결과 텍스트에 "카페라떼" 포함, changes[0].score == 1.0, changed는 False

**AC-02 · 한 글자 대체 오인식 교정**
- GIVEN: 가설 "자몽에이들 한 잔 주세요"
- WHEN: `correct()` (기본 threshold 0.65, 자몽에이들↔자몽에이드 유사도 0.8)
- THEN: 텍스트가 "자몽에이드..."로 교정되고 changed는 True

**AC-03 · 무관 문장 무교정**
- GIVEN: 가설 "안녕하세요 메뉴 추천해 주세요"
- WHEN: `correct()`
- THEN: changes가 비어 있고 text와 원문 정규화 결과가 동일, changed는 False

**AC-04 · Threshold 게이팅**
- GIVEN: 가설 "자몽에이들 한 잔" (자몽에이드와 유사도 0.8)
- WHEN: `CandidateMatcher(threshold=0.85).correct()` 와 `(threshold=0.75).correct()` 호출
- THEN: 0.85는 교정 안 함(changes 비어 있음), 0.75는 교정함

**AC-05 · 조사 보존**
- GIVEN: 가설 "카페라떼를 한 잔 주세요"
- WHEN: `correct()`
- THEN: 교정 구간이 "카페라떼"(4자)만이고 결과 텍스트에 "카페라떼를"이 유지됨

**AC-06 · 유사 메뉴 구분**
- GIVEN: 가설 "바닐라라떼 한 잔 주세요"와 "카페라떼 한 잔 주세요"
- WHEN: 각각 `correct()`
- THEN: 각자 자기 메뉴명으로 일치하며 서로 오교정되지 않음 (카페라떼 ↔ 말차라떼 0.5, ↔ 바닐라라떼 0.4 < 0.65)

**AC-06b · 환각 보정 차단**
- GIVEN: 가설 "아이스크림 주세요", "크로와상 주세요", "치즈케이크 주세요"
- WHEN: `correct()`
- THEN: changes가 비어 있고 교정되지 않음 (부분 단어/유사 단어는 토큰 길이 불일치로 후보 제외)

**AC-08b · 복수 단어 메뉴 교정**
- GIVEN: 가설 "크로플 아이스마림 한 잔 주세요" (크로플아이스크림 1자 오인식)
- WHEN: `correct()`
- THEN: "크로플아이스크림"으로 교정되고 changed는 True

**AC-07 · 띄어쓰기 무시**
- GIVEN: 가설 "카페 라떼 한 잔"
- WHEN: `correct()`
- THEN: "카페라떼"와 일치 처리, changed는 False (공백만 차이)

**AC-08 · 복수 메뉴 교정**
- GIVEN: 가설 "자몽에이들 한 잔 그리고 바스크치즈케이크 하나요"
- WHEN: `correct()`
- THEN: changes가 2건, 결과 텍스트에 "자몽에이드"와 "바스크치즈케이크" 모두 포함

**AC-09 · changed 플래그 의미**
- GIVEN: 정확 일치(변경 없음)와 한 글자 대체(변경 있음) 두 가설
- WHEN: 각각 `correct()`
- THEN: 전자는 changed=False, 후자는 changed=True

**AC-10 · 평가 스윕 출력 (S-16/S-17)**
- GIVEN: `compare_both_150_seed-42.csv` 존재
- WHEN: `compare_postprocess.py` 실행 (실제 데이터 + `--synthetic`, seed 42)
- THEN:
  - 실제 150샘플: 정답에 메뉴명 0건, 보정 0건, CER/WER 전후 동일
    (Baseline CER 0.2435 / QLoRA CER 0.2150, Baseline WER 0.4929 / QLoRA WER 0.4635)
  - 합성 스윕 표 (메뉴명 변형 발화 300건 기준, 교정성공/오교정/무교정/환각보정):
    - 0.65 → 300/0/0/0
    - 0.70 → 270/0/30/0
    - 0.75 → 270/0/30/0
    - 0.80 → 180/0/120/0
    - 0.85 → 60/0/240/0
  - 기본 Threshold 0.65 선정 (환각 보정 0건 + 교정 성공률 100% (300/300))
  - 전체 발화 기준 CER 0.1042 → 0.0000, WER 0.2632 → 0.0000 (0.65)
